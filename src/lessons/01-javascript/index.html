JavaScript는 값을 어떻게 다룰까요?

코드가 값을 만들고, 이름에 연결하고, 함수를 호출하는 과정을 이해합니다. 브라우저를 다루기 전에 실행의 기본 모델부터 잡습니다.

값과 계산을 구분하는 기준

  • 변수에 재대입하는 것과 객체의 속성을 수정하는 것을 구분합니다.
  • 함수 자체와 함수의 반환값을 구분하고 실행 시점을 설명합니다.
  • 클로저가 어떤 변수에 접근하는지 호출별로 추적합니다.
  • 조건에서 거짓으로 취급되는 값과 “없음”을 나타내는 값을 구분합니다.
  • this가 호출 방식으로 정해지는 이유와 예외가 실행을 끊는 방식을 설명합니다.

JavaScript는 무엇이고, 어디에서 실행될까요?

JavaScript는 값을 표현하고, 그 값으로 계산하고, 수행할 작업의 순서를 정하는 프로그래밍 언어입니다. “이름에 인사말을 붙인다”, “현재 개수에 하나를 더한다”, “조건에 맞을 때만 함수를 실행한다” 같은 규칙을 코드로 적을 수 있습니다. 코드는 그 자체로 화면이 아니며, 파일에 적힌 글자가 실행 환경에 전달되어야 실제 작업이 일어납니다.

언어의 규칙을 해석하고 실행하는 것은 JavaScript 엔진입니다. 브라우저는 이 엔진을 포함하면서 문서, 네트워크, 타이머처럼 웹페이지에 필요한 기능도 제공합니다. 엔진과 주변 기능을 포함하여 코드가 돌아가는 환경을 런타임이라고 부릅니다. 같은 JavaScript 언어라도 어디에서 실행하느냐에 따라 사용할 수 있는 주변 기능이 달라집니다.

예를 들어 숫자 두 개를 더하는 코드는 브라우저와 Node.js에서 모두 실행할 수 있습니다. 하지만 현재 웹 문서를 뜻하는 document는 브라우저 환경이 제공하는 객체입니다. 일반적인 Node.js 실행에는 웹페이지의 document가 없습니다. 따라서 JavaScript를 배운다는 것은 언어의 계산 규칙을 이해하는 일이고, DOM을 배운다는 것은 그 언어로 브라우저의 문서 기능을 사용하는 법을 이해하는 일입니다.

값에 이름을 붙여야 하는 이유

프로그램이 다루는 정보는 값으로 표현됩니다. 이름은 문자열, 완료한 개수는 숫자, 완료 여부는 불리언 값으로 나타낼 수 있습니다. 값에 이름을 붙이면 계산 도중의 결과를 다시 사용하고, 지금 어떤 정보를 다루는지 설명할 수 있습니다. 이 이름과 값의 연결이 변수입니다. 변수를 단순한 상자라고 생각해도 시작하는 데 도움이 되지만, 객체를 배울 때는 “이 이름이 어떤 값을 가리키는가”로 생각하는 편이 정확합니다.

let completed = 0은 completed라는 이름을 선언하고 숫자 0을 초기값으로 연결합니다. 뒤에서 completed = 1을 실행하면 같은 이름에 다른 값을 다시 대입합니다. 반면 const로 선언한 이름에는 다른 값을 다시 대입할 수 없습니다. let과 const의 차이는 값의 종류가 아니라 이름과 값의 연결을 바꿀 수 있는지에 있습니다.

대입은 수학의 등식과 다릅니다. completed = completed + 1은 양쪽이 영원히 같다는 선언이 아닙니다. 오른쪽에서 현재 값을 읽고 1을 더한 다음, 계산 결과를 왼쪽 이름에 저장하라는 작업입니다. 이미 그 값으로 만든 다른 문자열까지 거슬러 올라가 다시 계산하지는 않습니다. 화면도 별도의 코드를 통해 변경해야 합니다.

실행은 값을 계산하고 다음 작업으로 이동하는 과정

코드에서 값을 만들어내는 부분을 표현식이라고 합니다. 1 + 2, learner.name, describe("지우", 1)은 각각 계산, 속성 읽기, 함수 호출을 통해 값을 만듭니다. 프로그램은 이러한 표현식을 선언과 문장 안에 배치하여 작업을 구성합니다. 변수를 선언하고, 함수를 호출하고, 조건에 따라 분기하는 식으로 실행 흐름을 만듭니다.

한 작업 안에서도 순서가 있습니다. 함수에 전달할 표현식은 함수 본문으로 들어가기 전에 계산됩니다. 함수를 호출하면 실행은 잠시 그 함수 본문으로 이동하고, 함수가 끝나면 호출했던 자리 다음으로 돌아옵니다. return은 함수의 실행을 끝내면서 호출한 쪽에 값을 건네는 역할을 합니다. 명시적으로 값을 반환하지 않은 함수의 결과는 undefined입니다.

브라우저에서 외부 스크립트를 불러올 때는 파일 실행 시점도 필요합니다. 이 장은 <script defer src="main.js">로 파일을 연결합니다. 일반 외부 스크립트의 defer는 HTML을 읽는 동안 파일을 가져오되 문서 파싱이 끝난 뒤 실행하도록 합니다. 언어의 순서와 브라우저가 스크립트를 시작하는 시점은 서로 다른 문제입니다. 나중에 이벤트를 배우면 이미 실행을 마친 코드가 사용자 행동을 받아 다시 함수를 호출하는 과정까지 이어집니다.

작은 코드가 실행되는 과정을 한 줄씩 읽기

아래 코드는 화면 없이도 완결되는 계산입니다. 함수 선언의 본문과 실제로 실행되는 시점을 분리해서 읽어보면, 단순히 위에서 아래로 눈을 옮기는 것보다 실행 순서가 선명해집니다.

let completed = 0;
function describe(count) {
  return `${count}개 완료`;
}
completed = completed + 1;
const message = describe(completed);
console.log(message);
  1. 1행: completed라는 이름을 만들고 숫자 0을 초기값으로 연결합니다.
  2. 2행: describe라는 함수를 정의합니다. count는 나중에 호출할 때 전달받을 값의 이름입니다.
  3. 3행: 호출되었을 때 문자열을 만들어 반환할 작업입니다. 함수가 정의되었다고 이 줄이 즉시 실행되지는 않습니다.
  4. 4행: 함수 본문의 경계를 닫습니다. 함수 정의와 그 아래의 실제 계산을 구분합니다.
  5. 5행: 현재 값 0을 읽고 1을 더한 뒤 completed에 1을 다시 대입합니다.
  6. 6행: completed의 현재 값 1을 함수에 전달합니다. 함수 안의 count가 1이 되고, 반환된 “1개 완료”라는 문자열을 message에 연결합니다.
  7. 7행: 실행 환경의 console 기능에 문자열을 전달해 출력합니다. Console 출력 자체가 HTML 문서를 바꾸지는 않습니다.

이후 completed에 2를 대입해도 message는 “1개 완료”로 남습니다. message에는 함수 호출을 계속 추적하는 규칙이 아니라, 그때 호출하여 얻은 문자열이 들어 있기 때문입니다. 새 문구가 필요하면 함수를 다시 호출해야 합니다. 계산 결과와 계산 방법을 구분하는 것이 이후 DOM 갱신을 이해하는 출발점입니다.

원시 값을 바꾸는 것과 객체를 수정하는 것은 다릅니다

숫자·문자열·불리언 같은 원시 값 자체는 내부를 수정하는 대상이 아닙니다. 문자열에 글자를 붙이면 기존 문자열을 늘리는 것이 아니라 새 문자열을 얻습니다. let saved = completed로 숫자를 다른 이름에 대입한 뒤 completed에 새 숫자를 넣어도 saved는 그대로입니다. 두 이름 사이에 자동 동기화 관계가 생기지 않습니다.

객체는 여러 속성을 묶은 값이며, 자신만의 정체성을 갖습니다. 배열도 객체의 한 종류입니다. 객체를 다른 변수에 대입하면 객체 전체를 복제하는 대신 같은 객체를 가리키게 됩니다. const original = { done: false }; const alias = original; 뒤에 alias.done = true를 실행하면 original.done도 true입니다. 두 이름을 통해 같은 객체의 속성을 읽고 있기 때문입니다.

여기서 const의 의미가 분명해집니다. alias = 다른객체는 금지되어도 alias.done = true는 이름을 다른 값에 연결하는 작업이 아니므로 가능합니다. 또한 내용이 같은 객체를 따로 만들면 별개의 객체입니다. 객체의 === 비교는 속성 내용이 같은지보다 같은 객체를 가리키는지를 확인합니다. DOM에서 요소를 찾았을 때도 이런 참조를 받게 되므로, 이 구분이 다음 장으로 이어집니다.

함수는 작업을 전달하고, 범위는 값을 보관합니다

함수도 JavaScript의 값입니다. 변수에 담거나 다른 함수에 전달할 수 있습니다. 함수 이름만 쓴 describe는 함수를 가리키며, 괄호를 붙인 describe(1)은 그 함수를 지금 실행한 결과를 뜻합니다. 다른 함수에 전달되어 그 함수가 호출할 작업을 콜백이라고 부릅니다. 콜백은 별도 종류의 함수 문법이 아니라 그 함수가 맡은 역할입니다.

예를 들어 run(describe)는 run에게 함수를 전달합니다. run이 언제 호출하는지는 run의 구현에 달려 있습니다. 반면 run(describe(1))은 먼저 describe를 실행하고 그 결과 문자열을 전달합니다. 콜백이 항상 나중이나 비동기로 실행되는 것은 아닙니다. 함수 전달, 함수 호출, 호출 결과 전달은 서로 다른 작업입니다.

함수 안에서 이름을 읽을 때는 그 함수가 코드상 어디에서 정의되었는지가 중요합니다. 자기 범위에 없는 이름은 바깥 범위에서 찾습니다. 이 이름 탐색 규칙을 어휘적 범위, 즉 lexical scope라고 합니다. 호출한 곳의 변수 이름이 우연히 같다고 그 값을 사용하는 것이 아닙니다. 블록 안의 let·const, 함수의 매개변수처럼 이름을 사용할 수 있는 영역이 정해져 있습니다.

function createCounter() {
  let count = 0;
  return function next() {
    count += 1;
    return count;
  };
}
const next = createCounter();

createCounter를 호출하면 그 호출에 속한 count가 생깁니다. 반환된 next 함수는 자신이 정의된 바깥 범위의 count에 접근합니다. 바깥 함수의 실행이 끝나도 next를 통해 그 변수에 접근할 수 있는 관계가 유지됩니다. 함수와 이 주변 범위의 결합을 클로저라고 합니다. 그래서 next를 한 번 호출하면 1, 다시 호출하면 2를 반환할 수 있습니다. 매번 처음부터 새 count를 만드는 것이 아닙니다.

createCounter를 다시 호출하면 별개의 count와 함수가 만들어집니다. 한편 반환된 함수를 다른 변수에 대입하면 새 카운터가 생기는 것이 아니라 기존 함수를 함께 가리킵니다. 클로저는 초기 값을 얼려 놓은 사진도 아닙니다. 같은 변수의 이후 값을 계속 읽을 수 있습니다. 이런 방식으로 필요한 값만 함수 내부에 보관하면, 문서나 전역 변수에 의존하지 않는 작은 상태 관리 기능을 만들 수 있습니다.

지금까지의 핵심은 값, 이름, 객체, 실행을 구분하는 것입니다. 값은 계산의 결과이고, 변수는 그 값에 접근하는 이름이며, 객체는 공유할 수 있는 정체성을 갖습니다. 함수는 호출해야 작업을 실행하고, 필요한 값은 그 함수가 정의된 범위를 통해 이어집니다. 브라우저 화면을 다루는 코드도 이 언어 규칙 위에서 동작합니다.

조건은 값을 참과 거짓으로 나누어 읽습니다

if 문이나 &&, || 같은 연산자는 불리언이 아닌 값도 받습니다. 이때 값은 참이나 거짓 중 하나로 취급됩니다. 거짓으로 취급되는 값은 false, 0, -0, 0n, 빈 문자열 "", null, undefined, NaN뿐입니다. 이 값들을 falsy, 나머지 모든 값을 truthy라고 부릅니다. 그래서 문자열 "false"와 "0", 빈 배열 [], 빈 객체 {}는 모두 참으로 취급됩니다. 3장에서 볼 dataset처럼 값을 글자로만 저장하는 곳에 false를 넣으면 "false"라는 글자가 되는데, 이 글자는 조건문에서 참입니다.

두 값이 같은지 비교할 때는 ===를 사용합니다. ===는 값의 종류가 다르면 바로 false입니다. ==는 비교하기 전에 종류를 바꾸기 때문에 0 == ""나 "1" == 1이 true가 되는 것처럼 예측하기 어려운 결과를 만듭니다. 객체끼리의 ===는 앞에서 본 것처럼 같은 객체를 가리키는지를 비교합니다.

값이 없음을 나타내는 값은 두 가지입니다. undefined는 아직 값이 정해지지 않았다는 뜻입니다. 대입하지 않은 변수, 없는 속성, 아무것도 반환하지 않은 함수의 결과가 undefined입니다. null은 “대상이 없다”를 일부러 나타내는 값입니다. 2장에서 볼 요소 검색 함수 querySelector는 일치하는 요소가 없으면 null을 돌려줍니다. 둘 다 객체가 아니므로 그 뒤에서 속성을 읽으면 TypeError 예외가 발생합니다.

const learner = null;
const name = learner?.name;
const count = 0;
const a = count || 10;
const b = count ?? 10;
  1. 1행: 대상이 없다는 뜻으로 learner에 null을 대입합니다.
  2. 2행: ?.는 왼쪽이 null이나 undefined이면 속성을 읽지 않고 undefined를 돌려줍니다. 옵셔널 체이닝이라고 부릅니다. learner.name이라고 썼다면 여기서 예외가 발생합니다.
  3. 3행: 0은 “0개”라는 의미 있는 값입니다.
  4. 4행: ||는 왼쪽이 falsy이면 오른쪽 값을 고릅니다. 0도 falsy이므로 a는 10이 됩니다. 0개가 10개로 바뀐 셈입니다.
  5. 5행: ??는 왼쪽이 null이나 undefined일 때만 오른쪽 값을 고릅니다. 널 병합 연산자라고 부릅니다. b는 0으로 남습니다.

기본값을 정할 때 ||와 ?? 중 무엇을 쓸지는 “없음”을 어떻게 정의하느냐에 달려 있습니다. 0이나 빈 문자열이 정상적인 값이라면 ??를 사용합니다. 조건문도 마찬가지입니다. if (count)는 0을 “없음”과 같은 갈래로 보내므로, 값이 정해졌는지 확인하려면 count !== undefined처럼 기준을 드러내 쓰는 편이 정확합니다. 5장의 삭제 예제에서 ??로 “다음 항목이 없으면 이전 항목”을 고르는 코드를 다시 만나게 됩니다.

this는 함수를 호출한 방식으로 정해집니다

객체의 메서드 안에서는 this로 그 객체를 가리킬 수 있습니다. 그런데 this는 함수를 정의한 위치가 아니라 함수를 호출한 방식으로 정해집니다. 앞 절에서 본 어휘적 범위가 정의된 위치로 이름을 찾는 것과 반대입니다. counter.increase()처럼 점 앞에 객체를 두고 호출하면 this는 그 객체입니다.

const counter = {
  count: 0,
  increase() { this.count += 1; },
};
counter.increase();
const run = counter.increase;
run();
  1. 1~4행: count 속성과 increase 메서드를 가진 객체를 만듭니다. increase 안의 this.count는 호출될 때 정해질 객체의 count입니다.
  2. 5행: counter를 통해 호출하므로 this는 counter이고 count가 1이 됩니다.
  3. 6행: 메서드를 변수에 옮겨 담습니다. 함수 객체만 담길 뿐 counter와의 관계는 함께 담기지 않습니다.
  4. 7행: 점 앞의 객체 없이 호출하므로 this는 counter가 아닙니다. 엄격 모드에서는 this가 undefined라서 this.count를 읽는 순간 예외가 발생합니다. 엄격 모드가 아닌 일반 스크립트에서는 this가 브라우저 창 전체를 나타내는 전역 객체 window가 되어, counter가 아닌 엉뚱한 곳에 값을 씁니다.

엄격 모드는 실수하기 쉬운 몇 가지 동작을 조용히 넘기지 않고 오류로 알리도록 JavaScript의 규칙을 엄격하게 바꾼 실행 방식입니다. 파일 첫 줄에 "use strict"를 적으면 켜지고, 10장에서 다룰 모듈은 항상 엄격 모드로 실행됩니다. 이 장의 스크립트는 엄격 모드가 아닌 일반 스크립트입니다.

함수를 콜백으로 넘길 때 이 문제가 자주 생깁니다. setTimeout(counter.increase, 0)이나 button.addEventListener("click", counter.increase)는 6행처럼 함수만 넘깁니다. 특히 4장에서 다룰 이벤트 리스너로 넘긴 일반 함수는, 브라우저가 호출할 때 this를 리스너를 등록한 요소로 정합니다. 그래서 counter.count 대신 버튼 요소에 count라는 속성을 만들게 됩니다.

화살표 함수는 자신의 this를 갖지 않고, 정의된 위치 바깥의 this를 그대로 씁니다. () => counter.increase()처럼 화살표 함수로 감싸 넘기면 호출 방식이 다시 counter.increase()가 되어 문제가 사라집니다. 함수의 bind 메서드로 this를 고정한 새 함수를 만드는 방법도 있습니다. 이 교재의 카운터와 10장의 저장소가 this 대신 클로저로 값을 보관하는 것도 같은 이유입니다. 클로저는 정의된 위치에서 값을 찾으므로 함수를 어디로 넘기든 같은 값에 접근합니다.

예외는 지금의 실행을 끊고 바깥으로 전달됩니다

프로그램이 더 진행할 수 없는 상황을 만나면 예외가 발생합니다. null의 속성을 읽거나, 함수가 아닌 값을 호출하거나, 문법이 잘못된 선택자로 검색하면 실행 환경이 예외를 일으킵니다. 코드가 throw로 직접 예외를 일으킬 수도 있습니다. 예외가 발생하면 그 줄 다음은 실행되지 않고, 호출한 함수들을 거꾸로 거슬러 올라가며 예외를 처리할 곳을 찾습니다.

function setChecked(next) {
  if (typeof next !== "boolean") throw new TypeError("boolean이 필요합니다.");
  checked = next;
}
try {
  setChecked("true");
} catch (error) {
  console.log(error.message);
}
  1. 1~4행: 약속과 다른 종류의 값이 들어오면 TypeError 객체를 만들어 던집니다. 이 경우 throw 다음 줄의 대입은 실행되지 않습니다.
  2. 5~6행: try 블록 안에서 문자열 "true"로 호출합니다. 예외가 발생해 setChecked의 실행이 끝나고, try 블록에 남은 코드가 있다면 그것도 건너뜁니다.
  3. 7~9행: catch 블록이 던져진 오류 객체를 받아 메시지를 출력합니다. 예외를 처리했으므로 try 문 다음의 코드는 이어서 실행됩니다.

try로 감싸지 않은 예외는 현재 실행 중인 작업 전체를 끝내고 개발자 도구의 콘솔에 오류로 남습니다. 그렇다고 페이지 전체가 멈추지는 않습니다. 이벤트 리스너 하나에서 예외가 발생하면 그 리스너의 나머지 코드만 실행되지 않고, 같은 이벤트의 다른 리스너와 이후의 이벤트는 계속 처리됩니다. “버튼을 눌렀는데 일부만 바뀐다”는 증상을 만나면 콘솔에서 중간에 발생한 예외를 먼저 확인합니다.

모든 문제를 예외로 다루지는 않습니다. 검색 결과가 없는 것처럼 정상적으로 일어날 수 있는 상황은 null 검사 같은 조건으로 처리합니다. 10장에서 볼 상태 저장소가 boolean이 아닌 값을 받으면 TypeError를 던지는 것은 다른 경우입니다. 함수를 약속과 다르게 사용한 것이므로 조용히 넘어가지 않고 그 자리에서 알려 원인을 찾기 쉽게 합니다. finally 블록은 예외 여부와 관계없이 마지막에 실행되므로 정리 작업에 사용합니다.

한 번에 한 가지씩 실행하기

먼저 결과를 예상한 다음 버튼을 눌러보세요. 각 예제는 별개의 값을 사용합니다. 버튼과 결과 표시는 실험을 위한 DOM 코드이고, 코드 상자 안의 계산은 문서 없이도 실행할 수 있는 JavaScript입니다.

예제 1-1 · 값과 이름

다시 대입하면 이전 계산도 바뀔까요?

예상하기count에 2를 대입한 뒤 saved와 message는 어떤 값을 가질까요?

let count = 1;
const saved = count;
const message = `${count}개 완료`;
count = 2;

아직 실행하지 않았습니다.

확인할 결과count는 2, saved는 1, message는 “1개 완료”입니다. 대입과 문자열 계산은 그 줄이 실행될 때 한 번 일어납니다. 버튼을 다시 눌러도 매번 새 count에서 시작하므로 결과는 같습니다.

예제 1-2 · 객체의 정체성

같은 객체를 가리키는 이름과 새 객체

예상하기alias.done만 바꿨는데 original.done도 바뀔까요? separate는 어떨까요?

const original = { done: false };
const alias = original;
const separate = { done: false };
alias.done = true;

아직 실행하지 않았습니다.

확인할 결과original.done과 alias.done은 true, separate.done은 false입니다. original === alias는 true이고 original === separate는 false입니다. const는 재대입을 막지만 객체의 속성 수정을 막지는 않습니다.

예제 1-3 · 함수를 값으로 전달하기

함수는 언제 실행될까요?

예상하기콜백을 callback이라는 이름에 담는 순간 describe의 본문이 실행될까요?

let calls = 0;
function describe(count) {
  calls += 1;
  return `${count}개 완료`;
}
const callback = describe; // 아직 호출하지 않음
const message = callback(2); // 여기서 호출

아직 실행하지 않았습니다.

확인할 결과함수 전달 직후 calls는 0, callback(2) 호출 후에는 1입니다. callback에는 함수, message에는 “2개 완료”라는 문자열이 들어 있습니다. 콜백은 “다른 코드에 전달되어 호출되는 함수”라는 역할이며 항상 비동기인 것은 아닙니다.

예제 1-4 · 호출마다 생기는 범위

두 카운터는 각각 무엇을 기억할까요?

예상하기A를 두 번 실행한 뒤 B를 처음 실행하면 B도 3이 될까요?

function createCounter() {
  let count = 0;
  return () => ++count;
}
const nextA = createCounter();
const nextB = createCounter();

A: 0 · B: 0

확인할 결과A를 두 번, B를 한 번 실행하면 A: 2 · B: 1입니다. createCounter의 각 호출이 별개의 count를 만들고 반환된 함수가 그 변수에 접근합니다. 초기화는 두 함수를 새로 만듭니다.

예제 1-5 · 조건과 기본값

어떤 값이 “없음”으로 취급될까요?

예상하기0, 빈 문자열, "false", null 중에서 ||가 기본값으로 바꾸는 값은 무엇일까요? ??는 어떤 값만 바꿀까요?

Boolean(value);        // 조건에서 참으로 취급되는가
value || "기본값";
value ?? "기본값";

값을 하나 골라보세요.

확인할 결과0과 ""는 falsy라서 ||는 "기본값"으로 바꾸지만 ??는 그대로 둡니다. "false"와 []는 truthy이므로 두 연산자 모두 원래 값을 남깁니다. null과 undefined는 두 연산자 모두 기본값으로 바꿉니다. 결과의 따옴표는 문자열임을 보이기 위한 표시입니다.

예제 1-6 · 호출 방식과 this

메서드를 꺼내서 호출하면 this는 무엇일까요?

예상하기같은 report 함수를 네 가지 방식으로 호출합니다. this가 counter인 경우는 어느 것일까요?

const counter = { report() { return this; } };
counter.report();
const run = counter.report;
run();
const wrapped = () => counter.report();
wrapped();
button.addEventListener("click", counter.report);

아직 호출하지 않았습니다.

확인할 결과counter.report()와 wrapped()에서 this는 counter입니다. wrapped는 화살표 함수 안에서 다시 counter.report()로 호출하기 때문입니다. run()에서는 일반 스크립트의 전역 객체 window입니다. 이 장의 스크립트는 엄격 모드가 아닌 일반 스크립트이므로 undefined가 아니라 window가 나옵니다. 리스너로 등록된 report는 this가 리스너가 등록된 버튼 요소입니다.
