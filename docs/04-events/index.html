이벤트는 어떻게
코드에 도착할까요?

이벤트는 발생한 일을 코드에 알려주는 방식입니다. 이벤트를 받는 함수를 등록하는 일부터, 그 함수가 호출되는 시점과 문서 안의 전달 경로까지 차례로 이해합니다.

이벤트는 발생한 사실을 전달하는 객체입니다

사용자가 버튼을 누르거나 입력창의 내용을 바꾸면 브라우저는 그 일을 자바스크립트 코드에 알려줄 수 있습니다. 이렇게 “무언가 발생했다”는 사실을 전달하는 체계가 이벤트입니다. 이벤트 자체가 화면을 바꾸는 함수는 아닙니다. 무엇이 일어났는지를 전달하면, 그 사실을 받은 코드가 필요한 일을 결정합니다.

코드가 받는 것은 이벤트 객체입니다. 객체에는 발생한 일의 종류를 나타내는 type, 대상인 target 등의 정보가 들어 있습니다. 키보드 이벤트라면 어떤 키인지, 포인터 이벤트라면 좌표가 무엇인지처럼 종류에 맞는 정보도 포함됩니다. 따라서 “클릭했다”는 사실과 “클릭했으니 문구를 바꾼다”는 처리는 서로 분리됩니다.

특정 대상에 특정 종류의 이벤트를 받겠다고 연결하는 것을 리스너 등록이라고 합니다. 등록된 뒤 실제 처리를 담당하는 함수는 이벤트 핸들러라고 부릅니다. 실무에서는 리스너라는 말로 이 함수까지 가리키기도 합니다. 중요한 것은 등록 정보와 실행할 함수가 연결된다는 점입니다.

이 함수는 우리가 그 자리에서 호출하지 않고 다른 코드에 전달해 둡니다. 전달받은 쪽이 정해진 조건에 호출하는 함수를 콜백이라고 합니다. 이벤트 핸들러는 콜백의 한 사례입니다. “콜백”은 함수의 문법이나 비동기 실행을 뜻하지 않고, 누가 그 함수를 호출하는지에 관한 말입니다.

발생 사실과 처리 방법을 분리하는 이유

코드를 위에서 아래로 한 번 실행하는 것만으로는 사용자가 나중에 무엇을 누를지 알 수 없습니다. 입력창 값을 계속 반복해서 확인하는 것도 불필요한 일을 늘립니다. 대신 브라우저에 관심 있는 일을 등록해 두면, 그 일이 발생한 순간 필요한 함수를 실행할 수 있습니다. 문서를 준비하는 코드와 사용자 행동에 반응하는 코드가 이 지점에서 연결됩니다.

같은 동작은 여러 입력 방식에서 시작될 수도 있습니다. 폼 제출은 제출 버튼으로 시작할 수도 있고 입력창의 Enter 키에서 시작할 수도 있습니다. “어떤 마우스 버튼을 눌렀는가” 대신 “폼을 제출하려 한다”는 이벤트를 처리하면, 입력 수단마다 같은 로직을 중복해서 작성할 필요가 줄어듭니다. 이벤트를 고르는 일은 우리가 어떤 의미의 행동을 처리하려는지 정하는 일이기도 합니다.

등록, 호출, 전달 경로는 서로 다른 단계입니다

등록할 때는 함수를 전달합니다

button.addEventListener("click", handleClick)은 버튼의 click 이벤트와 handleClick 함수를 연결합니다. 함수 이름 뒤에 괄호가 없으므로 여기서 함수 본문을 실행하지 않습니다. handleClick()이라고 쓰면 지금 함수를 호출하고, 그 반환값을 addEventListener에 넘기게 됩니다. 함수 객체를 전달하는 표현과 함수 호출 표현의 차이가 실행 시점을 결정합니다.

나중에 이벤트가 전달되면 브라우저가 핸들러를 호출하면서 이벤트 객체를 인수로 줍니다. 핸들러의 매개변수 이름을 event라고 정했다면 그 안에서 event.target을 읽을 수 있습니다. event라는 전역 변수가 자동으로 만들어진다고 이해해서는 안 됩니다. 매개변수를 통해 받은 값을 읽는 것입니다.

브라우저의 사용자 입력과 코드의 직접 전달

사용자의 클릭을 처리하는 일은 일반적으로 현재 실행 중인 자바스크립트 작업이 끝난 뒤 브라우저가 다음 작업으로 진행합니다. 하지만 이벤트 핸들러가 언제나 나중에 호출되는 것은 아닙니다. 코드에서 dispatchEvent를 호출하면 그 호출 안에서 관련 핸들러가 실행되고, 처리가 끝나야 다음 줄로 넘어갑니다. 이런 실행을 동기 실행이라고 합니다.

예를 들어 “준비됨”이라는 자체 이벤트를 만들고 전달할 수도 있습니다. 직접 전달한 이벤트는 사용자가 실제로 조작했다는 사실과 같지 않으며, 일반적으로 사용자 입력의 모든 기본 동작을 재현하지도 않습니다. 이벤트를 전달하는 기능과 입력 장치를 흉내 내는 기능을 같은 것으로 생각하지 않는 것이 좋습니다.

문서 안에서 내려갔다 올라오는 경로

버튼 안의 span에서 클릭이 시작되면 이벤트는 해당 요소만의 일이 아닙니다. 대상의 조상에서 대상 쪽으로 내려가는 캡처 단계, 대상 자체에서 처리하는 단계, 조상 쪽으로 올라가는 버블 단계로 전달될 수 있습니다. 부모에 기본 방식으로 등록한 click 리스너는 버블 단계에서 호출됩니다. 캡처 시점에 받으려면 등록할 때 capture 옵션을 true로 지정합니다.

이 예에서 target은 이벤트의 출발 대상인 span이고, currentTarget은 지금 실행하는 핸들러가 등록된 요소입니다. 같은 이벤트라도 버튼 핸들러에서는 currentTarget이 버튼, 부모 핸들러에서는 부모입니다. 모든 이벤트가 버블링하는 것은 아니므로 이 경로는 이벤트 종류의 특성과 함께 이해해야 합니다.

작은 코드에서 호출 시점 읽기

아래는 이미 찾은 button 요소에 notice라는 자체 이벤트를 연결하는 짧은 코드입니다. notice는 예제를 위해 정한 이름이며 버튼의 기본 동작과는 관계가 없습니다.

function handleNotice(event) {
  console.log("B", event.type);
}
button.addEventListener("notice", handleNotice);
console.log("A");
button.dispatchEvent(new Event("notice"));
console.log("C");
  1. function handleNotice(event)는 함수를 정의합니다. 아직 로그를 출력하지 않으며, 나중에 받은 객체를 event라는 이름으로 읽도록 준비합니다.
  2. 함수 안의 console.log는 호출될 때만 실행됩니다. 여기서는 B와 이벤트 종류를 출력하는 처리입니다.
  3. addEventListener는 함수 자체를 등록합니다. 함수 정의와 등록만 끝난 시점에도 B는 출력되지 않습니다.
  4. 첫 console.log가 A를 출력합니다. 그다음 new Event는 notice라는 종류의 객체를 만들고 dispatchEvent가 버튼에 전달합니다.
  5. 전달 도중 핸들러가 호출되어 B와 notice가 출력됩니다. dispatchEvent가 반환한 뒤 마지막 줄이 C를 출력하므로 순서는 A → B → C입니다.

연결이 필요 없어지면 같은 요소에서 같은 종류와 함수로 removeEventListener("notice", handleNotice)를 호출합니다. 본문이 같은 새 함수를 만들면 다른 함수 객체이므로 기존 연결을 지우지 못합니다. 캡처로 등록했다면 해제할 때도 같은 capture 값을 사용해야 합니다.

이벤트 전달과 기본 동작을 구분하기

브라우저는 요소에 따라 기본 동작을 제공합니다. 링크의 이동, 폼 제출, 체크박스의 선택 변경 등이 그 예입니다. 이벤트를 받아 실행하는 우리 코드와 이러한 기본 동작은 별개의 부분입니다. 취소 가능한 기본 동작을 막는 preventDefault는 이벤트가 부모에 전달되는 것을 막지 않습니다.

반대로 stopPropagation은 다음 요소로 이벤트가 전파되는 것을 멈춥니다. 폼의 submit 전파를 멈추어도 그 자체로 기본 제출을 취소하지는 않습니다. 이미 실행된 조상의 캡처 핸들러를 되돌리지도 않습니다. “부모가 알지 못하게 한다”와 “브라우저가 원래 하려던 일을 하지 않게 한다”를 구분하면 두 메서드의 역할이 분명해집니다.

input, change, submit도 서로 다른 사실을 전달합니다. 텍스트 입력의 input은 사용자 편집으로 값이 바뀌는 동안 발생합니다. change는 값의 변경이 확정될 때 발생하며, 텍스트 입력에서는 값을 바꾼 뒤 포커스를 옮길 때 관찰할 수 있습니다. 체크박스의 change는 선택을 바꾸는 순간 발생합니다. submit은 개별 입력의 변화가 아니라 폼 제출의 시도를 뜻합니다.

프로그램에서 value나 checked만 대입하면 input이나 change가 자동으로 발생하지 않습니다. 값이 바뀌었다는 사실과 특정 이벤트가 발생했다는 사실은 같은 조건이 아니기 때문입니다. 화면을 갱신할 목적이라면 필요한 함수를 직접 호출할 수 있으며, 이벤트를 일부러 만들어 보내야 하는 것은 아닙니다.
