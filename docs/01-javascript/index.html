JavaScript는 값을 어떻게 다룰까요?

코드가 값을 만들고, 이름에 연결하고, 함수를 호출하는 과정을 이해합니다. 브라우저를 다루기 전에 실행의 기본 모델부터 잡습니다.

언어와 실행 환경값과 변수실행 흐름한 줄씩 읽기값과 객체함수와 범위

JavaScript는 무엇이고, 어디에서 실행될까요?

JavaScript는 값을 표현하고, 그 값으로 계산하고, 수행할 작업의 순서를 정하는 프로그래밍 언어입니다. “이름에 인사말을 붙인다”, “현재 개수에 하나를 더한다”, “조건에 맞을 때만 함수를 실행한다” 같은 규칙을 코드로 적을 수 있습니다. 코드는 그 자체로 화면이 아니며, 파일에 적힌 글자가 실행 환경에 전달되어야 실제 작업이 일어납니다.

언어의 규칙을 해석하고 실행하는 것은 JavaScript 엔진입니다. 브라우저는 이 엔진을 포함하면서 문서, 네트워크, 타이머처럼 웹페이지에 필요한 기능도 제공합니다. 엔진과 주변 기능을 포함하여 코드가 돌아가는 환경을 런타임이라고 부릅니다. 같은 JavaScript 언어라도 어디에서 실행하느냐에 따라 사용할 수 있는 주변 기능이 달라집니다.

예를 들어 숫자 두 개를 더하는 코드는 브라우저와 Node.js에서 모두 실행할 수 있습니다. 하지만 현재 웹 문서를 뜻하는 document는 브라우저 환경이 제공하는 객체입니다. 일반적인 Node.js 실행에는 웹페이지의 document가 없습니다. 따라서 JavaScript를 배운다는 것은 언어의 계산 규칙을 이해하는 일이고, DOM을 배운다는 것은 그 언어로 브라우저의 문서 기능을 사용하는 법을 이해하는 일입니다.

값에 이름을 붙여야 하는 이유

프로그램이 다루는 정보는 값으로 표현됩니다. 이름은 문자열, 완료한 개수는 숫자, 완료 여부는 불리언 값으로 나타낼 수 있습니다. 값에 이름을 붙이면 계산 도중의 결과를 다시 사용하고, 지금 어떤 정보를 다루는지 설명할 수 있습니다. 이 이름과 값의 연결이 변수입니다. 변수를 단순한 상자라고 생각해도 시작하는 데 도움이 되지만, 객체를 배울 때는 “이 이름이 어떤 값을 가리키는가”로 생각하는 편이 정확합니다.

let completed = 0은 completed라는 이름을 선언하고 숫자 0을 초기값으로 연결합니다. 뒤에서 completed = 1을 실행하면 같은 이름에 다른 값을 다시 대입합니다. 반면 const로 선언한 이름에는 다른 값을 다시 대입할 수 없습니다. let과 const의 차이는 값의 종류가 아니라 이름과 값의 연결을 바꿀 수 있는지에 있습니다.

대입은 수학의 등식과 다릅니다. completed = completed + 1은 양쪽이 영원히 같다는 선언이 아닙니다. 오른쪽에서 현재 값을 읽고 1을 더한 다음, 계산 결과를 왼쪽 이름에 저장하라는 작업입니다. 이미 그 값으로 만든 다른 문자열까지 거슬러 올라가 다시 계산하지는 않습니다. 화면도 별도의 코드를 통해 변경해야 합니다.

실행은 값을 계산하고 다음 작업으로 이동하는 과정

코드에서 값을 만들어내는 부분을 표현식이라고 합니다. 1 + 2, learner.name, describe("지우", 1)은 각각 계산, 속성 읽기, 함수 호출을 통해 값을 만듭니다. 프로그램은 이러한 표현식을 선언과 문장 안에 배치하여 작업을 구성합니다. 변수를 선언하고, 함수를 호출하고, 조건에 따라 분기하는 식으로 실행 흐름을 만듭니다.

한 작업 안에서도 순서가 있습니다. 함수에 전달할 표현식은 함수 본문으로 들어가기 전에 계산됩니다. 함수를 호출하면 실행은 잠시 그 함수 본문으로 이동하고, 함수가 끝나면 호출했던 자리 다음으로 돌아옵니다. return은 함수의 실행을 끝내면서 호출한 쪽에 값을 건네는 역할을 합니다. 명시적으로 값을 반환하지 않은 함수의 결과는 undefined입니다.

브라우저에서 외부 스크립트를 불러올 때는 파일 실행 시점도 필요합니다. 이 장은 <script defer src="main.js">로 파일을 연결합니다. 일반 외부 스크립트의 defer는 HTML을 읽는 동안 파일을 가져오되 문서 파싱이 끝난 뒤 실행하도록 합니다. 언어의 순서와 브라우저가 스크립트를 시작하는 시점은 서로 다른 문제입니다. 나중에 이벤트를 배우면 이미 실행을 마친 코드가 사용자 행동을 받아 다시 함수를 호출하는 과정까지 이어집니다.

작은 코드가 실행되는 과정을 한 줄씩 읽기

아래 코드는 화면 없이도 완결되는 계산입니다. 함수 선언의 본문과 실제로 실행되는 시점을 분리해서 읽어보면, 단순히 위에서 아래로 눈을 옮기는 것보다 실행 순서가 선명해집니다.

let completed = 0;
function describe(count) {
  return `${count}개 완료`;
}
completed = completed + 1;
const message = describe(completed);
console.log(message);
  1. 1행: completed라는 이름을 만들고 숫자 0을 초기값으로 연결합니다.
  2. 2행: describe라는 함수를 정의합니다. count는 나중에 호출할 때 전달받을 값의 이름입니다.
  3. 3행: 호출되었을 때 문자열을 만들어 반환할 작업입니다. 함수가 정의되었다고 이 줄이 즉시 실행되지는 않습니다.
  4. 4행: 함수 본문의 경계를 닫습니다. 함수 정의와 그 아래의 실제 계산을 구분합니다.
  5. 5행: 현재 값 0을 읽고 1을 더한 뒤 completed에 1을 다시 대입합니다.
  6. 6행: completed의 현재 값 1을 함수에 전달합니다. 함수 안의 count가 1이 되고, 반환된 “1개 완료”라는 문자열을 message에 연결합니다.
  7. 7행: 실행 환경의 console 기능에 문자열을 전달해 출력합니다. Console 출력 자체가 HTML 문서를 바꾸지는 않습니다.

이후 completed에 2를 대입해도 message는 “1개 완료”로 남습니다. message에는 함수 호출을 계속 추적하는 규칙이 아니라, 그때 호출하여 얻은 문자열이 들어 있기 때문입니다. 새 문구가 필요하면 함수를 다시 호출해야 합니다. 계산 결과와 계산 방법을 구분하는 것이 이후 DOM 갱신을 이해하는 출발점입니다.

원시 값을 바꾸는 것과 객체를 수정하는 것은 다릅니다

숫자·문자열·불리언 같은 원시 값 자체는 내부를 수정하는 대상이 아닙니다. 문자열에 글자를 붙이면 기존 문자열을 늘리는 것이 아니라 새 문자열을 얻습니다. let saved = completed로 숫자를 다른 이름에 대입한 뒤 completed에 새 숫자를 넣어도 saved는 그대로입니다. 두 이름 사이에 자동 동기화 관계가 생기지 않습니다.

객체는 여러 속성을 묶은 값이며, 자신만의 정체성을 갖습니다. 배열도 객체의 한 종류입니다. 객체를 다른 변수에 대입하면 객체 전체를 복제하는 대신 같은 객체를 가리키게 됩니다. const original = { done: false }; const alias = original; 뒤에 alias.done = true를 실행하면 original.done도 true입니다. 두 이름을 통해 같은 객체의 속성을 읽고 있기 때문입니다.

여기서 const의 의미가 분명해집니다. alias = 다른객체는 금지되어도 alias.done = true는 이름을 다른 값에 연결하는 작업이 아니므로 가능합니다. 또한 내용이 같은 객체를 따로 만들면 별개의 객체입니다. 객체의 === 비교는 속성 내용이 같은지보다 같은 객체를 가리키는지를 확인합니다. DOM에서 요소를 찾았을 때도 이런 참조를 받게 되므로, 이 구분이 다음 장으로 이어집니다.

함수는 작업을 전달하고, 범위는 값을 보관합니다

함수도 JavaScript의 값입니다. 변수에 담거나 다른 함수에 전달할 수 있습니다. 함수 이름만 쓴 describe는 함수를 가리키며, 괄호를 붙인 describe(1)은 그 함수를 지금 실행한 결과를 뜻합니다. 다른 함수에 전달되어 그 함수가 호출할 작업을 콜백이라고 부릅니다. 콜백은 별도 종류의 함수 문법이 아니라 그 함수가 맡은 역할입니다.

예를 들어 run(describe)는 run에게 함수를 전달합니다. run이 언제 호출하는지는 run의 구현에 달려 있습니다. 반면 run(describe(1))은 먼저 describe를 실행하고 그 결과 문자열을 전달합니다. 콜백이 항상 나중이나 비동기로 실행되는 것은 아닙니다. 함수 전달, 함수 호출, 호출 결과 전달은 서로 다른 작업입니다.

함수 안에서 이름을 읽을 때는 그 함수가 코드상 어디에서 정의되었는지가 중요합니다. 자기 범위에 없는 이름은 바깥 범위에서 찾습니다. 이 이름 탐색 규칙을 어휘적 범위, 즉 lexical scope라고 합니다. 호출한 곳의 변수 이름이 우연히 같다고 그 값을 사용하는 것이 아닙니다. 블록 안의 let·const, 함수의 매개변수처럼 이름을 사용할 수 있는 영역이 정해져 있습니다.

function createCounter() {
  let count = 0;
  return function next() {
    count += 1;
    return count;
  };
}
const next = createCounter();

createCounter를 호출하면 그 호출에 속한 count가 생깁니다. 반환된 next 함수는 자신이 정의된 바깥 범위의 count에 접근합니다. 바깥 함수의 실행이 끝나도 next를 통해 그 변수에 접근할 수 있는 관계가 유지됩니다. 함수와 이 주변 범위의 결합을 클로저라고 합니다. 그래서 next를 한 번 호출하면 1, 다시 호출하면 2를 반환할 수 있습니다. 매번 처음부터 새 count를 만드는 것이 아닙니다.

createCounter를 다시 호출하면 별개의 count와 함수가 만들어집니다. 한편 반환된 함수를 다른 변수에 대입하면 새 카운터가 생기는 것이 아니라 기존 함수를 함께 가리킵니다. 클로저는 초기 값을 얼려 놓은 사진도 아닙니다. 같은 변수의 이후 값을 계속 읽을 수 있습니다. 이런 방식으로 필요한 값만 함수 내부에 보관하면, 문서나 전역 변수에 의존하지 않는 작은 상태 관리 기능을 만들 수 있습니다.

지금까지의 핵심은 값, 이름, 객체, 실행을 구분하는 것입니다. 값은 계산의 결과이고, 변수는 그 값에 접근하는 이름이며, 객체는 공유할 수 있는 정체성을 갖습니다. 함수는 호출해야 작업을 실행하고, 필요한 값은 그 함수가 정의된 범위를 통해 이어집니다. 브라우저 화면을 다루는 코드도 이 언어 규칙 위에서 동작합니다.
