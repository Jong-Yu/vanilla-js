# 바닐라 JS와 DOM — 읽기 안내

이 자료는 JavaScript와 브라우저 문서 모델을 개념부터 설명하는 교재입니다. 각 장은 정의와 필요성, 작동 원리, 짧은 코드의 줄별 해설 순서로 이어집니다. JavaScript·DOM·이벤트·상태·브라우저 실행·폼·접근성·재사용을 11개 장으로 다룹니다. 실행 예제는 개념 본문 뒤에 있고, 코드를 수정하는 연습은 마지막에 선택 항목으로 접혀 있습니다.

## 실행하기

[GitHub Pages에서 바로 읽기](https://jong-yu.github.io/vanilla-js/) — 설치 없이 본문과 예제를 실행하고 코드를 수정해볼 수 있습니다.

[단일 HTML 파일](dist/vanilla-js-dom.html)을 브라우저에서 열면 본문과 예제가 함께 들어 있습니다. CSS와 JavaScript를 따로 준비할 필요가 없습니다. 각 장의 앞부분은 읽는 본문이며, 예제는 설명한 동작을 확인하고 싶을 때 사용합니다.

코드를 더 살펴보려면 **코드 보기**를 열고, 수정한 내용은 **예제에 적용**으로 실행합니다. 수정 내용은 현재 파일이 열린 동안만 유지됩니다. 파일을 다시 열거나 새로고침하면 원본으로 돌아옵니다. 개발자 도구에서 예제의 document를 관찰할 때는 본문이 표시된 iframe을 선택합니다.

[개념별 예제 목록](samples.html)에서는 한 가지 질문에 집중한 35개 예제를 바로 찾을 수 있습니다. 예제 주소는 단일 HTML 안에서도 해당 위치로 이동합니다.

원본으로 단일 파일을 다시 생성하려면 Node.js 18 이상에서 `node build.mjs`를 실행합니다. 출력은 `dist/vanilla-js-dom.html`이며, `samples.html`도 각 장의 실제 예제 제목으로 다시 생성됩니다. 예제 목록을 직접 수정하는 대신 해당 장의 `class="sample"` 섹션 제목과 내용을 고치세요. `npm test`로 상태 변경·구독·초기화 검사를 실행할 수 있습니다.

여러 파일로 된 원본을 보려면 이 폴더에서 `python3 -m http.server 4173 --bind 127.0.0.1`을 실행하고 [로컬 페이지](http://127.0.0.1:4173)를 엽니다.

## GitHub Pages 배포

GitHub 저장소에서는 이 교재의 원본을 `docs/`에 보관합니다. `main`의 교재 파일이 변경되면 GitHub Actions가 테스트와 `npm run build:pages`를 실행하고 생성된 `docs/_site/`를 배포합니다. 이 로컬 교재 폴더에서는 `npm run build:pages`를 실행하면 `_site/`가 생성됩니다.

공개 첫 화면은 코드 편집기가 포함된 단일 HTML이며 기존 장별 주소와 `dist/vanilla-js-dom.html` 주소도 유지합니다. 미리보기 이미지와 빌드 스크립트는 배포 파일에서 제외합니다. Pages의 게시 방식은 **GitHub Actions**를 사용합니다.

각 예제는 개별 상태를 가집니다. 반복 비교가 필요한 예제에는 초기화 버튼을 두었습니다. 장 전체를 처음 상태로 되돌리려면 단일 파일의 **예제 다시 시작**을 누르거나 원본 페이지를 새로고침합니다. 10장의 두 입력처럼 하나의 예제 안에서 상태를 공유하는 경우에는 공유 관계를 명시했습니다.

## 처음에 구분할 세 가지

**JavaScript는 언어**입니다. 값을 계산하고, 변수에 대입하고, 함수를 호출하는 규칙을 표현합니다. 엔진은 이 규칙을 실행합니다. 브라우저는 엔진이 사용할 수 있도록 문서와 이벤트, 타이머 등의 기능을 제공합니다.

**DOM은 문서를 객체로 표현한 모델**입니다. 브라우저가 HTML을 읽어 만든 노드들이 부모와 자식 관계로 연결됩니다. JavaScript는 DOM API를 호출해 이 구조를 찾고 바꿉니다. HTML 문자열을 편집하는 일, 실행 중인 DOM을 바꾸는 일, 화면에 픽셀을 그리는 일은 서로 다른 단계입니다.

**바닐라 JavaScript는 별도 언어가 아닙니다.** 여기서는 프레임워크를 거치지 않고 JavaScript와 브라우저의 기본 API를 사용하는 방식을 뜻합니다. HTML 안에 JavaScript를 넣어도 HTML이 프로그래밍 언어로 바뀌는 것은 아닙니다. 한 파일에 들어 있는 각 언어의 역할을 나누어 읽습니다.

참고: [MDN — DOM 소개](https://developer.mozilla.org/en-US/docs/Web/API/Document_Object_Model/Introduction).

## 읽는 순서

### 언어와 문서의 관계

[1장 — 값, 변수, 함수와 실행](01-javascript/)은 이름에 값을 대입하는 일과 함수를 실행하는 일을 설명합니다. 원시 값과 객체 참조, 콜백, 변수의 범위와 클로저를 이해하면 뒤에서 같은 함수와 상태를 여러 곳에서 사용하는 이유가 보입니다.

[2장 — HTML에서 DOM 객체까지](02-dom/)는 HTML 문자열이 어떻게 문서 트리가 되는지 설명합니다. 요소를 찾았을 때 받는 것은 문자열 복사본이 아니라 실제 객체를 가리키는 참조입니다. Node와 Element, 부모와 자식, 선택자와 목록을 이 관점에서 읽습니다.

[3장 — 문서의 내용과 현재 상태](03-dom-update/)는 HTML의 선언과 실행 중인 요소의 상태를 구분합니다. attribute와 property, 입력의 기본값과 현재값, 텍스트 교체와 스타일 적용이 서로 어떻게 연결되는지 설명합니다.

### 문서에서 행동과 상태로

[4장 — 이벤트가 행동을 전달하는 원리](04-events/)는 등록된 함수가 어떤 과정을 거쳐 호출되는지 설명합니다. 이벤트 객체, 캡처와 버블링, target과 currentTarget, 전파와 기본 동작의 차이를 각각의 역할로 이해합니다.

[5장 — DOM 트리의 생성과 변경](05-dom-create/)는 객체를 만드는 일과 문서에 연결하는 일을 구분합니다. 같은 노드의 이동과 새로운 노드의 복제, 제거된 객체의 참조, 부모에서 여러 자식의 이벤트를 처리하는 위임을 이어서 설명합니다.

[6장 — 상태와 화면의 연결](06-state-render/)은 화면의 원본 데이터와 그 값에서 계산하는 표현을 구분합니다. 메모리의 값과 DOM이 자동으로 연결되지 않는 이유, 값을 바꾸는 경로를 모으는 이유, 누가 값을 결정할지 정하는 방법을 다룹니다.

### 브라우저의 동작과 재사용 구조

[7장 — 브라우저의 실행 순서](09-browser-runtime/)는 동기 실행과 예약된 작업, task와 microtask, DOM 변경과 layout·paint의 관계를 설명합니다. 코드가 실행되는 순서와 사용자가 화면을 보는 시점을 구분합니다.

[8장 — 폼과 포커스의 기본 계약](10-focus-forms/)은 브라우저가 기본 요소에 제공하는 행동을 설명합니다. 포커스와 선택, Tab 순서와 프로그램 이동, 폼 데이터의 이름과 포함 규칙, 현재값과 초기화의 관계를 다룹니다.

[9장 — 접근성의 의미와 동작](11-accessibility/)은 DOM과 접근성 트리의 차이, 컨트롤의 이름·역할·상태·설명을 구분합니다. 네이티브 요소의 키보드 동작, label, 펼침 상태와 숨김, 포커스를 옮기지 않는 결과 알림을 각각 작은 예제로 확인합니다. ARIA가 실제 동작을 대신 구현하지 않는 이유도 설명합니다.

[10장 — 동작을 재사용하는 구조](07-headless/)는 상태 계산, DOM 연결, 시각 표현을 분리하는 이유를 설명합니다. 저장소와 구독을 일반 객체와 함수의 관계로 읽고, 헤드리스와 프레임워크 독립이 각각 어떤 구분인지 연결합니다.

[11장 — 연결과 수명](08-lifecycle/)은 등록한 함수가 왜 남는지, 정리 함수가 무엇을 기억하는지 설명합니다. 기능을 시작하고 끝내는 일, 여러 연결을 한 책임으로 묶는 일, 예약한 작업의 취소를 앞 장들의 개념으로 해석합니다.

## 용어를 읽는 기준

| 용어 | 이 교재에서 뜻하는 것 |
| --- | --- |
| 값 | 프로그램이 계산하거나 저장하는 데이터 |
| 참조 | 특정 객체에 접근할 수 있게 하는 값 |
| 속성(property) | 객체에 이름을 붙여 보관한 값 |
| 메서드(method) | 객체를 통해 호출하는 함수 |
| API | 다른 코드가 기능을 사용할 수 있도록 공개한 약속 |
| 상태(state) | 현재 상황을 나타내며 시간에 따라 바뀔 수 있는 데이터 |
| 이벤트(event) | 발생한 사실을 전달하는 객체와 전달 과정 |
| 콜백(callback) | 다른 코드가 호출할 수 있도록 전달한 함수 |
| 구독(subscription) | 변화가 있을 때 호출할 함수를 등록하는 관계 |
| 접근 가능한 이름 | 보조 기술이 요소를 식별하는 데 사용하는 이름 |
| 포커스(focus) | 현재 키보드 입력을 받을 위치 |
| 접근성 트리 | 브라우저가 보조 기술에 노출할 의미와 상태를 구성한 표현 |
| 정리(cleanup) | 기능의 필요가 끝났을 때 등록과 예약을 해제하는 작업 |

## 이 교재와 디자인 시스템의 관계

디자인 시스템의 헤드리스 동작을 구현할 때는 브라우저가 이미 제공하는 규칙과 직접 작성해야 할 규칙을 구분해야 합니다. 이 책의 언어·DOM·이벤트·상태·포커스 개념은 그 판단의 바탕입니다. 마지막 두 장은 이 지식을 재사용 가능한 코드 구조로 묶는 출발점입니다.

복잡한 Dialog의 포커스 제어, 메뉴의 키보드 탐색, 화면 밖으로 나가지 않는 위치 계산 등은 각각 추가 설계가 필요한 주제입니다. 기본 개념을 알고 나면 이 기능들도 관련된 상태, 요소, 이벤트, 연결 수명으로 나누어 이해할 수 있습니다.

## 접근성을 직접 확인하기

마우스를 내려놓고 Tab·Shift+Tab으로 이동하며 포커스가 보이는지 확인합니다. 버튼은 Enter와 Space, 체크박스는 Space로 조작합니다. 펼침 예제는 열림 상태와 실제 표시가 일치하고, 숨겨진 내용에는 Tab이 들어가지 않아야 합니다. 결과 알림 예제에서는 실행한 버튼에 포커스가 남아야 합니다.

스크린 리더에서는 이름·역할·상태·설명이 전달되는지 확인합니다. 접근성 패널의 속성 확인과 실제 낭독 검사는 별개의 확인입니다. 브라우저와 보조 기술의 조합에 따라 표현과 안내 시점이 다를 수 있으며, 이 교재의 예제만으로 전체 접근성 적합성을 판정하지는 않습니다.
